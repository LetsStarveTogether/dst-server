# `0x72020000` Localization, Skins, and Scrapbook

This page separates text translation, skin presentation, and Scrapbook data into three display pipelines.
Skins also affect prefab builds, images, and sounds.
Scrapbook entries are generated snapshots, while seen, viewed, and inspected state is runtime data.

## `0x72021111` Data Roles

`STRINGS` is the base text table, and `TranslateStringTable(STRINGS)` recursively replaces its values.
`skin_assets` lists assets, while `prefabskins.lua` maps prefabs to skin names.
`prefabskin.lua` applies skin appearance and selected sounds at runtime.
`clothing.lua` and `misc_items.lua` provide collection metadata.
`prefabs/skinprefabs.lua` provides the concrete skin Prefabs.
`clothing.lua`, `misc_items.lua`, and `prefabskins.lua` are generated account-item tables.
`prefabs/skinprefabs.lua` is generated by the same `export_accountitems.lua` process.
`skin_assets.lua`, `skin_gifts.lua`, `skin_strings.lua`, and `skins_defs_data.lua` are coordinated exporter outputs.
`scrapbookdata.lua` is a snapshot generated by `d_createscrapbookdata()`.

## `0x72021211` Runtime State Boundary

`ScrapbookScreen` reads seen, viewed, and character-inspection state from `TheScrapbookPartitions`.
Its entry presentation data comes from `screens/redux/scrapbookdata.lua`.

Find `function TranslateStringTable`, then inspect `local function DoTranslateStringTable`.

### `0x72023111` Translation

`Translator:LoadPOFile` supports reference and `msgctxt` fields.
It stores translated values in `self.languages[lang]`.
`main.lua` translates once for early boot consumers and again after `ModManager:LoadMods()` so mod-added strings are included.

### `0x72023211` Skin Presentation

`skin_assets.lua` returns dynamic assets such as `Asset("DYNAMIC_ANIM", ...)` and `Asset("PKGREF", ...)`.
Presentation also depends on `skin_strings.lua`, `skins_defs_data.lua`, `prefabskins.lua`, and `skinsutils.lua`.
`prefabskin.lua` applies entity changes such as inventory images and animation symbol overrides.
The skin list includes `walrushat_minigolf_green`, `walrushat_minigolf_purple`, and `walrushat_minigolf_red`.
Their matching `tophat_minigolf_*` granted-item paths award them and bind them through `AddSkinLinkInput`.
They are also in `ITEM_DISPLAY_BLACKLIST`, preventing ordinary item presentation.
Release group 184 adds nine `SEASIDE` outfits, a beach mystery box, and parasol, pitchfork, shovel, and waterballoon skins.
`PREFAB_SKINS.waterballoon` lists `waterballoon_insect` as a dependency of the base Prefab.
`CreatePrefabSkin` separately registers its descriptor with `waterballoon_init_fn`.
The two registrations meet at the engine's prefab-spawn boundary.
The held-symbol override then runs in `prefabs/waterprojectiles.lua`.
Its equip and unequip events feed the existing `WorldOverseer` worn-item accounting.
The unskinned path and projectile behaviour remain unchanged.
`skin_gifts.lua` classifies the waterballoon item, portrait, and profile flair as `TWITCH_DROP` entries.
It classifies `mysterybox_beach` as `DEFAULT`.
`body_wathgrithr_ancient` now overrides its character-specific `arm_upper_skin` symbol instead of hiding it.

### `0x72023311` Scrapbook Snapshot

`d_createscrapbookdata()` generated the file, so treat it as an auditable snapshot.
It is not handwritten gameplay logic.
Runtime unlock, read, and character-inspection state comes from `scrapbookpartitions.lua`, not the snapshot.
Scrapbook data records the `chesspiece_vault_pillar_guard` build and golden pickaxe finite uses.
It also records Vault object animation names and dependencies.
`prefabs/vault_key_activator.lua` sets `scrapbook_anim`, which supplies animation data during generation.

### `0x72023411` WX-78 Fishing Text

`speech_wx78.lua` contains blue and green spoon-lure descriptions.
`languages/strings.pot`, `languages/chinese_s.po`, and `languages/chinese_t.po` contain the matching `msgid` values.
Text investigations must therefore include both character speech files and the translation templates.

### `0x72023511` Online and Offline Text

`strings.lua` defines store-login, online/offline world-conversion, and premium-online membership text.
No tracked Lua file consumes the new keys directly.
Treat them as a presentation contract rather than evidence of a new in-tree screen flow.

## `0x72024111` Translation Keys

`DoTranslateStringTable` recursively builds a unique key from the table path.
It first asks `LanguageTranslator:GetTranslatedString(path)` for a replacement.

## `0x72024211` Scrapbook Filtering

`SetPlayerKnowledge` writes `knownlevel` from seen and inspected state; viewed state only controls new-entry markers.
`CollectType` applies category and knowledge visibility, while `FilterData` applies text search.
`BuildItemGrid` sorts and renders the result.

## `0x72024311` Skin Ownership Boundary

Skin assets, text, and `PREFAB_SKINS` only describe available skins.
Trace ownership and selection through `TheInventory:CheckOwnership`, the collection UI, and `skinsutils.lua`.
These paths also enforce event restrictions.
`ValidateRecipeSkinRequest` performs the authoritative check for server recipe requests before `Builder` uses a skin.
It checks client ownership, membership in the base Prefab's skin list, and the event lock.
For an incorrect entity appearance, inspect the initializer in `prefabskin.lua`.
For held or equippable items, also inspect the base Prefab's equip and unequip callbacks.
